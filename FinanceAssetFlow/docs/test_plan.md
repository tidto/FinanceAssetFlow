# 테스트 계획

## 1. 테스트 목표

FinanceAssetFlow의 핵심 테스트 목표는 다음과 같다.

1. Room DB 기반 CRUD가 정상 동작하는지 검증한다.
2. 금융 계산 로직이 정확한지 검증한다.
3. 입력 검증과 오류 피드백이 UI에서 제공되는지 검증한다.
4. Compose 화면 이동과 주요 사용자 흐름이 정상 동작하는지 검증한다.
5. lint 또는 정적 분석을 통해 기본 품질 문제를 확인한다.

## 2. 테스트 실행 환경

| 구분 | 실행 명령 |
| --- | --- |
| 단위 테스트 | `./gradlew test` |
| Android 계측 테스트 | `./gradlew connectedAndroidTest` |
| 정적 분석 | `./gradlew lint` |
| 전체 빌드 | `./gradlew assembleDebug` |

Windows PowerShell 환경에서는 다음과 같이 실행한다.

```powershell
.\gradlew.bat test
.\gradlew.bat connectedAndroidTest
.\gradlew.bat lint
.\gradlew.bat assembleDebug
```

## 4. 단위 테스트 케이스

### T-LOGIC-01. 순자산 계산

- [ ] 자산 2건과 부채 1건이 있을 때 순자산이 `총자산 - 총부채`로 계산된다.
- [ ] 자산이 없고 부채만 있을 때 순자산이 음수로 계산된다.
- [ ] 자산과 부채가 모두 없을 때 모든 합계가 0이다.

### T-LOGIC-02. 투자자산 평가손익 계산

- [ ] 매입금액 1,000,000원, 평가금액 1,200,000원이면 평가손익은 200,000원이다.
- [ ] 매입금액 1,000,000원, 평가금액 900,000원이면 평가손익은 -100,000원이다.
- [ ] 매입금액이 0 또는 null이면 수익률 계산 결과는 null 또는 표시 불가 상태다.

### T-LOGIC-03. 분류별 비율 계산

- [ ] 총자산 10,000,000원 중 예적금 5,000,000원이면 예적금 비율은 50%다.
- [ ] 총자산이 0이면 모든 비율은 0으로 처리한다.
- [ ] 부채는 자산 분류 비율 계산에서 제외한다.

### T-VALIDATION-01. 자산 입력 검증

- [ ] 자산명이 비어 있으면 저장할 수 없고 오류 메시지를 표시한다.
- [ ] 금액이 비어 있으면 저장할 수 없고 오류 메시지를 표시한다.
- [ ] 금액이 음수이면 저장할 수 없고 오류 메시지를 표시한다.
- [ ] 투자자산에서 평가금액만 입력하고 매입금액이 없으면 안내 메시지를 표시한다.

## 5. Room DAO 테스트 케이스

### T-DB-01. AssetDao CRUD

- [ ] AssetEntity insert 후 id가 반환된다.
- [ ] getAllAssets에서 생성한 자산이 조회된다.
- [ ] update 후 변경된 금액이 조회된다.
- [ ] delete 후 목록에서 제거된다.

### T-DB-02. AssetHistoryDao

- [ ] 자산 생성 시 CREATED 이력이 저장된다.
- [ ] 자산 금액 수정 시 UPDATED 이력이 저장된다.
- [ ] 특정 assetId로 이력 목록을 조회하면 해당 자산의 이력만 반환된다.

### T-DB-03. PortfolioTargetDao

- [ ] 목표 비율을 저장하면 조회된다.
- [ ] 같은 category의 목표를 다시 저장하면 갱신된다.

## 6. ViewModel 테스트 케이스

### T-VM-01. DashboardUiState

- [ ] Repository의 자산 Flow가 변경되면 총자산, 총부채, 순자산 상태가 갱신된다.
- [ ] 빈 데이터 상태에서는 빈 목록과 0원 집계가 표시된다.
- [ ] 투자자산 평가금액 변경 후 대시보드 총자산이 갱신된다.

### T-VM-02. AssetEditUiState

- [ ] 입력값 변경 시 UiState가 갱신된다.
- [ ] 유효하지 않은 입력으로 저장을 시도하면 저장 로직이 실행되지 않는다.
- [ ] 유효한 입력으로 저장하면 Repository insert 또는 update가 호출된다.

## 7. Compose UI 테스트 케이스

### T-UI-01. 대시보드 화면

- [ ] 앱 타이틀이 표시된다.
- [ ] 총자산, 총부채, 순자산 카드가 표시된다.
- [ ] 자산 목록 카드가 표시된다.
- [ ] 자산 추가 버튼을 누르면 등록 화면으로 이동한다.

### T-UI-02. 자산 등록 화면

- [ ] 필수 입력란이 표시된다.
- [ ] 자산명 미입력 후 저장하면 오류 문구가 표시된다.
- [ ] 금액에 숫자가 아닌 문자를 입력할 수 없거나 저장 시 차단된다.
- [ ] 저장 성공 후 대시보드로 돌아간다.

### T-UI-03. 자산 상세 화면

- [ ] 자산명, 분류, 금액, 메모가 표시된다.
- [ ] 투자자산이면 평가손익과 수익률이 표시된다.
- [ ] 수정 버튼을 누르면 수정 화면으로 이동한다.
- [ ] 삭제 버튼을 누르면 확인 다이얼로그가 표시된다.

## 8. 테스트 결과 기록 방식

테스트 실행 후 `docs/test_result.md`에 다음 항목을 기록한다.

- 실행 일자
- 실행 환경
- 실행 명령
- 성공/실패 여부
- 실패 케이스 및 원인
- 수정 후 재실행 결과
